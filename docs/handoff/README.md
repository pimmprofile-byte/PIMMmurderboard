# 핸드오프 문서

플레이 세션을 **개발 세션과 다른 세션에서** 돌리기 위한 문서다.

## 왜 나누나

개발 세션은 시나리오 파일을 전부 읽었기 때문에 범인과 트릭을 알고 있다.
그 상태로 진행을 맡기면 아무리 조심해도 새어 나간다. 그래서 진행은
아무것도 모르는 새 세션에 맡긴다.

핵심은 **문서에 답을 안 적는 것**이 아니라, **애초에 답을 못 보게 하는 것**이다.
서버가 이미 그 경계를 지키고 있다.

| 등급 | 내용 | 누가 보나 |
|---|---|---|
| 공개 | 규칙, 페이즈, 배역 공개 프로필, 지도, 공개된 카드 | 전원 |
| 진행 | 각 배역 손패 내용, 차례, 채점 현황 | 진행 세션 (`AGENT_KEY` 필요) |
| 배역 비밀 | 개인 시트·목표·비밀 | **그 배역을 맡은 사람만** |
| 진상 | 범인, 동기, 트릭, 엔딩 분기 | **아무 API로도 안 나간다. 서버 안에만 있다** |

진행 세션은 위 세 등급까지만 볼 수 있다. 네 번째는 코드상 접근 경로가 없다.
`/api/sheet/{배역}`은 그 배역을 실제로 맡은 클라이언트가 아니면 403이다.

## 문서 두 장

| 파일 | 누가 읽나 |
|---|---|
| `플레이세션_운용법.md` | **사람**. 뭘 어디에 주고 어떤 순서로 굴리는지 |
| `진행세션_핸드오프.md` | **진행 세션**. 통째로 붙여넣는 본문 |

## 쓰는 법

1. 새 세션을 연다 (Haiku 권장 — 응답이 빨라야 대화가 붙는다).
2. `진행세션_핸드오프.md`를 통째로 붙여넣는다.
3. 렌더 주소와 `AGENT_KEY`를 알려준다.
   **`AGENT_KEY`는 이 저장소에 넣지 않는다.** 렌더 환경변수에만 둔다.
4. 시작한다.

**진행 세션에 이 깃 저장소를 붙이지 않는다.** `scenarios/`에 진상이 들어 있다.
문서 한 장과 주소·키만 넘긴다. 자세한 건 `플레이세션_운용법.md`.

## 개발 세션 쪽 규칙

개발 세션(이 저장소를 고치는 세션)에서는 진상을 다뤄야 할 때가 있다.
그때도 채팅에 진상을 그대로 출력하지 않는다. 파일을 고칠 때는 고치고,
설명은 "어느 카드가 어느 쌍과 붙는다" 수준까지만 한다.

플레이 예정일이 잡히면 개발 세션에서 시나리오 내용 이야기를 아예 멈추는 게 낫다.
